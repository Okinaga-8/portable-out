01

先に結論

同じ環境で動く

10Eros-Max は MiniMax H3 のファインチューン。H3 の全 50 ブロックをそのまま保持し、block 0–31 の fused QKV だけを差し替えた派生。ComfyUI 本体・text encoder・VAE・ワークフローは今のまま使える。

落とすのは 1 ファイル

追加ダウンロードは diffusion model 1 本だけ。約 12 GB（GGUF Q4_K_M）〜 21 GB（INT8）。15.7 GB の text encoder も 5 GB の VAE も、落とし直す必要はない。

16GB の本命

beta2 ref2va の GGUF Q4_K_M（約 11.6 GB）＋ ComfyUI-GGUF。Turbo が焼き込まれていない版なので、いまの「Turbo で下書き → 外して本番」がそのまま通る。

つまり「同じ環境で試したい」という見立ては当たっています。作業としては ComfyUI の入れ直しでも、環境の作り直しでもなく、モデルファイルを 1 本増やしてローダーの参照先を切り替えるだけ です。既存の H3 ファイルは消さずに残してください。同一シード・同一プロンプトで A/B できることが、このモデルを試す一番の価値なので。

ただし、モデルより先に確認してほしいことが 1 つ

FL2VA と Ref2VA は Turbo LoRA を共有しません。別モデルなので、LoRA も別物です。Ref2VA 用は minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors ただ 1 つ。もし Ref2VA の生成に FL2VA 用の Turbo LoRA（…fl2v… / larryvrh 系 / lightx2v 8step など）を当てていたなら、10Eros-Max 以前に、そこが品質を落としている可能性があります。今夜いちばん最初に見てください。詳細は 07。

02

用語の整理と、1 点だけ訂正

呼び方が紛らわしいところがあるので、先に固めておきます。

「10Eros」には別系統が 2 つある 混同注意

同じ作者（TenStrip）が、まったく違うベースモデルに同じブランド名を付けています。検索でヒットしたものをそのまま落とすと、動かないファイルを 20 GB 掴むことになります。

10Eros 系 2 系統
名前ベース今回見分け方
10Eros-MaxMiniMax H3◯ これファイル名に h3 が入る。10Eros_Max_h3_…
LTX2.3-10ErosLTX-Video 2.3× 別物リポジトリ名が LTX2.3-10Eros。VAE も text encoder（Gemma 3）も H3 と別物なので流用不可

10Eros-Max は「LTX 2.3・Wan 2.2・Krea 2 から性格を移植した H3 派生」と説明されています。名前に LTX 系の血が入っているのはそのためで、動く土台はあくまで H3 です。

「チェックポイントを差し替える」ではなく「diffusion model を差し替える」

SD1.5 や SDXL の感覚だと 1 個の checkpoint に全部入っていますが、H3 は DiT（本体）＋ text encoder ＋ video VAE ＋ audio VAE の 4 点セットで、ComfyUI 上でも別々のローダーで読みます。差し替え対象はこのうち DiT だけです。

モード名：FL2VA と Ref2VA、そして「hybrid」

  • FL2VA（first-and-last-frame）— 画像 0 枚なら T2V、1 枚なら I2V、2 枚なら始点＋終点指定。
  • Ref2VA（omni-reference）— 画像 9 枚・動画 3 本・音声 3 本まで参照として渡せるモード。キャラや声を寄せたいとき用。VRAM 的にはこちらの方が重い。

この 2 つは別モデルです。DiT ファイルも別なら、Turbo LoRA も別。そして設計上、Ref2VA は FL2VA より素の画質・音質が明確に落ちます（参照条件付けができる代わりの対価）。これは H3 の既知の性質で、あなたが主に Ref2VA を使っているなら、10Eros-Max が謳う「顔の一貫性の向上」はまさにそこに効く可能性があります。相性は良さそうです。

hybrid とは何か 使い方に制約あり

この Ref2VA の品質差を埋めるために、コミュニティは FL2VA をベースに、50 ブロックのうち一部の adaln_proj だけを Ref2VA から取ってくるマージを作っています。これが「hybrid」。10Eros-Max の TURBO-hybrid 系もこの系譜で、1 ファイルで参照モードと t2va の両方を賄えます。両モードを使うあなたには効率が良い形です。

hybrid を i2v モードで使わないこと

hybrid 系は 参照（ref2va）形式か t2va 形式で使うもので、i2v モードでは使わない、という注意が付いています。画像 1 枚を渡す場合も、first_frame ではなく参照画像として ref2va 形式で渡します。ここを間違えると「なぜか品質が出ない」になります。

「作風が少し異なる」の中身 補足

10Eros-Max の差分として挙がっているのは、静止画的な「画風」よりも 動きの性格 です。具体的には 顔の一貫性の向上 と 弾むような、反応の速いモーション。ダンスなど動きの大きい題材に向く、という評価です。逆に言うと、静かなカットで A/B しても差が見えにくい可能性があります。比較用のプロンプトは動きのあるものにしてください。

03

何を差し替えるのか

現状の 4 点セットのうち、色の付いた 1 箱だけが入れ替わります。残りは触りません。

ファイル名は ComfyUI 公式構成での標準的な組み合わせです。お使いの環境と一致するかは 04 で確認してください。

audio VAE を fp16 に落とさないこと

audio VAE を fp16 化すると映像と音がズレる、という報告が繰り返し出ています。VRAM を削りたくなっても、ここは fp32 のままにしてください。

04

帰宅後の手順

上から順に。00〜02 はダウンロードを始める前に済ませてください。ここで得た値が、そのまま 05 の選択を決めます。

  1. 現状を吐き出す（5 分）

    リポジトリの tools/h3_env_check.py を ComfyUI のフォルダを指定して実行すると、GPU・VRAM・ドライバ・ComfyUI のバージョン・models 配下の H3 関連ファイル・空きディスクを Markdown で出力します。

    git pull
python tools/h3_env_check.py --comfy "C:\path\to\ComfyUI"

    出た内容を 10 環境メモ に貼るか、そのままチャットに貼ってください。これがあると以降の判断がぶれません。

  2. Turbo LoRA のファイル名を確認する 最優先

    Ref2VA のワークフローの LoRA ローダーを開き、ファイル名に ref2v が入っているかを見ます。入っていなければ FL2VA 用を当てています。その場合は minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors に差し替え、NFE 4 / shift video 12・audio 3 に合わせて 1 本回してください。ここが直るだけで印象が変わる可能性があります。詳細は 07。

  3. いま使っている DiT ファイル名を確認する

    「Load Diffusion Model」ノードで選ばれているファイル名を見ます。ref2va / fl2va のどちらか、pruned が付くか、を控えます。Ref2VA 側を主に使うので、まず落とすのは 10Eros-Max の ref2va 版です。

  4. 空きディスクを確認する

    GGUF Q4_K_M なら 12 GB、INT8 なら 22 GB 空けます。ダウンロード中は一時ファイルも要るので、実際は +5 GB 見ておくと安全。

  5. ComfyUI-GGUF を入れる（GGUF を選ぶ場合のみ）

    ComfyUI Manager から ComfyUI-GGUF（city96）を導入 → ComfyUI 再起動。INT8 版で行くなら不要です。

  6. モデルを 1 本落とす

    05 の表から 1 行だけ選んで落とす。既存の H3 ファイルは消さない。

  7. いつものワークフローを複製し、ローダーだけ差し替える

    ワークフローを「名前を付けて保存」で複製 → DiT のローダーだけ 10Eros-Max に向ける（GGUF なら Load Diffusion Model を Unet Loader (GGUF) に置換）。他は一切触らない。

  8. まず 1 本、小さく回す

    低解像度（0.2 MP 前後 = 608×352 など）・短尺（3〜5 秒）・少ステップで 1 本。ここで見るのは画質ではなく「落ちないか」だけです。OOM が出たら 06 の順に削ります。

  9. 同一シードで A/B を 4〜6 本

    既存 H3 と 10Eros-Max で、シード・プロンプト・解像度・ステップを完全に揃えて回します。動きのある題材で。結果と時間・ピーク VRAM を 11 実測ログ に記録してください。次のチャットはその数字を起点に詰めます。

06

16GB に載るのか

結論から言うと載ります。ただし「4 つ全部を同時に VRAM に置く」わけではない、という前提の理解が要ります。

同時常駐はしない

ファイルサイズを単純合計すると 40 GB を超えますが、ComfyUI は text encoder でプロンプトを符号化 → 解放 → DiT でサンプリング → 解放 → VAE でデコード と順番に載せ替えます。ピーク VRAM を決めるのは基本的に DiT ＋ 潜在テンソルです。そのため、GGUF Q4_K_M（11.6 GB）＋ 16 GB は現実的な組み合わせになります。

64 GB の物理メモリはここで効きます。12 GB 級の実測レポートでは「32 GB でも動くが、64 GB が offload ボトルネックの根本的な解決になる」と明記されています。16 GB VRAM ＋ 64 GB RAM は、この用途としてかなり素直な構成です。

報告されている癖：長いクリップの方が VRAM 使用量が少なくなることがある（ComfyUI がモデルを VRAM から追い出すため）。直感に反しますが複数の報告があります。

Ref2VA 固有：参照画像のリサイズ方針

蒸留学習では ref_image_size の match（参照画像の面積を目標キャンバスに合わせ、アスペクト比は保持、拡大はしない）を使っています。Turbo LoRA を使うなら match を選ぶのが公式の推奨です。既定が diffusers（短辺 2048 固定）になっていると、学習時と条件がずれます。

使い所音が要る本番、A/B の基準数を打つ下書き、両モードを 1 本で回したいとき

順序としては beta2 が先です。いまの運用（base ＋ Turbo LoRA、外して本番）をそのまま維持でき、変数が「モデルだけ」に絞れます。beta4 はそのあと、Turbo LoRA を外した状態で、step を 6〜8 に、必要なら sampler を LCM/simple にして試してください。そして beta4 は i2v 形式で使わないこと（02）。

ほかに、10Eros-Max の test4 pruned 系専用に変換された Turbo LoRA も存在します（t8star、約 795 MB / 1.96 GB、INT8 ConvRot）。ただし一部は「dual-clock サンプラーが必要、もしくは 8〜10 step で使うこと」と注記されています。これは 3 本目以降の話で、最初から手を出すと切り分けが効かなくなります。

変わらない原則

  • pruned 版には pruned 用の Turbo LoRA を。フル版向け（larryvrh 等 744 MB）と pruned 用（drbaph/Abiray 等 592 MB）は別物です。10Eros-Max の GGUF は pruned 由来。
  • Turbo は音を確実に劣化させる。複数の実測レポートで一致。「Turbo で下書き → 気に入ったシードだけ Turbo なしで本番」が定石。
  • Turbo は VRAM を減らさない。OOM 対策にはなりません。

4080 での期待値（推定）

上の表から外挿すると、0.4〜0.6 MP・5 秒・8 step で 2〜5 分程度が最初の当たりでしょう。CUDA は 13 で済んでいるので、上の 5080 の行（約 300 秒 @1 MP）が現実的な参照点になります。

これより桁が違って遅い場合、残る容疑者は順に attention バックエンド（--use-ck-attention を試す）、不要な --lowvram、Ref2VA そのものの重さ（参照画像の枚数を減らす）、そして Turbo LoRA のモード違い（07）です。この推定値の当否は 11 で確かめたい点のひとつ。

Ref2VA は T2V に比べて VRAM も時間も明確に重いという報告が複数あります。参照画像の枚数がそのまま効くので、A/B のときは枚数も揃えてください。

09

確定していること／実機で確かめること

このシートで一番大事な節です。調べて裏が取れたことと、あなたの機械でしか判定できないことを分けてあります。次のチャットは右側から始めます。

確定 複数ソースで一致

  • 10Eros-Max は H3 アーキテクチャを完全に保持し、block 0–31 の fused QKV のみ改変。DmitryDB の量子化版はカスタムノードも本体パッチも不要と明記。
  • text encoder は Qwen3-VL-32B。10Eros-Max でも変わらない。
  • FL2VA と Ref2VA は別モデルで、Turbo LoRA を共有しない。Ref2VA 用は 4-step v0.1 の 1 種類のみ。
  • beta4 には非 Turbo 版が存在しない。作者が「非 Turbo 版は出来が悪い」として作っていない。
  • hybrid 系は i2v モードで使わない。参照（ref2va）形式か t2va 形式で使う。
  • Ref2VA は設計上、FL2VA より素の画質・音質が落ちる。VRAM も時間も重い。
  • audio VAE は fp32 必須（fp16 で A/V ズレ）。
  • ComfyUI は 0.30.0 以降が必要（音声サンプラー修正が 2026-08-06 に入っている）。W4A8 は 0.31.0 以降。
  • DT-sQKV 版は本体パッチが必要。
  • Turbo LoRA は音を劣化させる。VRAM は減らさない。step だけ変えても成立せず、shift も合わせる必要がある。
  • NVFP4 のネイティブ演算は Blackwell（SM 10.0）世代の機能で、Ada（SM 8.9）にはない。
  • 回答済 CUDA は 13。4080 系で最も効いた既知の改善策は、すでに適用済み。
  • 回答済 使用モードは FL2VA / Ref2VA 両方、主に Ref2VA。Turbo LoRA を使用中。

要検証 実機でしか分からない
