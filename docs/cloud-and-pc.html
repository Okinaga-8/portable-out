Claude Code のしくみ

クラウドと PC の受け渡し

スマホで始めたチャットと、PC で始めたチャットは何が違うのか。portable-out とは何なのか。GitHub はどこに関係しているのか。いつ見返しても分かるように書いたものです。

大前提：Claude Code は「1 つのフォルダ」しか見ていない

ここが分かると、あとは全部つながります。

Claude Code は、起動したときに決まった 1 つのフォルダの中だけを見て、その中のファイルを読んだり書いたりするアシスタントです。それ以上でも以下でもありません。

スマホで始めたときと PC で始めたときの違いは、「そのフォルダがどこにあるか」だけです。仕組みが違うわけではありません。

Q1

portable-out とは何か

あなたが GitHub に作った、フォルダ 1 個分の置き場所です。正式には「リポジトリ」と呼びます。

正式な名前は Okinaga-8/portable-out。スラッシュの前があなたのアカウント名、後ろがそのフォルダにつけた名前です。2026 年 7 月に作られていて、説明文には「code drop-box（成果物の受け渡し箱）」と書いてあります。

中身は、いまのところこんなものです。

  • README.md … 説明書き
  • WORKFLOW.md … 使い方の手順
  • docs/ … 資料（このページもここに入っています）
  • tools/ … 実行できる小さなプログラム

つまり 「特別な何か」ではなく、ただのフォルダです。ただし置いてある場所が、あなたの PC ではなく GitHub というインターネット上の保管庫だ、というのが唯一のポイントです。

GitHub とは

ファイルを預かって、いつ・誰が・どこを変えたかを全部記録してくれる保管庫です。世界中のプログラマが使っていますが、あなたのように「複数の場所から同じフォルダを触りたい」人にとっては、要するに履歴つきのオンライン倉庫だと思えば十分です。

Q2

「クラウド上の使い捨てパソコン」とは何か

スマホやブラウザから Claude Code のチャットを始めると、その瞬間に インターネットの向こう側で、あなた専用の小さなパソコンが 1 台起動します。

本物のパソコンと同じように、OS が入っていて、プログラムを動かせて、インターネットにもつながります。ただし 画面もキーボードもなく、私だけが使います。

そのパソコンは、起動した直後に GitHub から portable-out をまるごとコピーして、自分の中に置きます。私が「作業フォルダ」として見ているのは、このコピーです。

そして名前のとおり 使い捨てです。チャットが終わって時間が経つと、そのパソコンごと丸ごと捨てられます。中にあったものは全部消えます。

逆に言えば、この使い捨てパソコンには あなたの PC のファイルは 1 つも入っていません。だから私は C:\ComfyUI の中身を見ることができず、「フォルダの中身を貼ってください」と何度もお願いすることになります。意地悪をしているわけではなく、物理的に見えないのです。

Q3

portable-out と GitHub の関係

一言でいうと 「原本と写し」です。

原本は GitHub にあります。クラウドの使い捨てパソコンにあるのも、あなたの PC にあるのも、どちらも写し（コピー）です。3 つの場所に同じフォルダがあるように見えますが、正式なものは GitHub のものだけ、と考えてください。

ここが Google ドキュメントとの一番の違いです。Google ドキュメントは全員が原本を直接いじりますが、この仕組みでは 各自が写しを持って手元で作業し、区切りのいいところでまとめて原本に送り返します。

面倒に見えますが、利点があります。いつ・どこを・なぜ変えたかが全部記録に残るので、あとから「あの時どうしたんだっけ」を追えますし、間違えても元に戻せます。

覚える操作は 3 つだけ

専門用語が出てきますが、意味はこれだけです。

用語やっていること言い換えると
clone（クローン）原本を、はじめて手元にコピーする取り寄せる（初回だけ）
pull（プル）手元の写しを、原本の最新に合わせる受け取る
commit / push手元で変えたところを、原本に反映する発送する

commit が「荷造り（変更のまとまりに名前をつけて箱に入れる）」、push が「発送」です。私が作業のたびに 2 つ並べて報告しているのは、そのためです。

何が、どこにあるのか

混乱しやすいところなので、表にしておきます。

ものある場所
portable-out の原本GitHub消えない
その写しクラウドの使い捨てパソコンチャット終了後に消える
その写しあなたの PC消えない
ComfyUI 本体とモデルファイルあなたの PC だけ消えない
チャットの会話Claude 側新しいチャットには引き継がれない

4 行目が大事です。ComfyUI のモデルファイルは GitHub にもクラウドにも一切ありません。20 GB もあるものを置く場所ではありませんし、置く意味もありません。ファイル名とサイズさえ分かれば、判断はできます。

5 行目も大事です。私は会話を覚えていません。新しいチャットを開いた瞬間、記憶はゼロに戻ります。

だから HANDOFF.md がある

会話は引き継げませんが、フォルダの中のファイルは読めます。だから「いまどこまで進んだか」を HANDOFF.md というただのメモ帳に書いて、原本に送り返しておきます。次のチャットでは、私にそれを読ませれば続きから始められます。

特別な仕組みではありません。置き手紙です。

おまけ：「ブランチ」とは何か

私の報告に claude/minimax-10eros-comfyui-setup-23yatw という長い名前が出てきて、混乱させてしまいました。これは ブランチといいます。

原本の中には、本棚と作業台があると思ってください。

  • 本棚（main）… 完成したものを置く、正式な場所
  • 作業台（ブランチ）… 作業中のものを一時的に広げておく場所

作業台を使うのは、途中の状態で本棚を汚さないためです。気に入らなければ作業台ごと捨てられます。

結局、あなたは何をすればいいのか

git のコマンドは覚えなくて構いません。日本語で頼めば、Claude Code がやります。

PC のデスクトップアプリを、いつもの作業フォルダで開いて、こう言うだけです。

GitHub の Okinaga-8/portable-out を、このフォルダに持ってきて。
ブランチは claude/minimax-10eros-comfyui-setup-23yatw を使って。
そのあと HANDOFF.md を読んで、続きから始めて。

これで PC 側の Claude が、取り寄せも、置き手紙を読むところまでも全部やります。以降は「最新にして」「送り返して」で通じます。

逆に、スマホ側で調べ物を頼んだときは、最後にこう言っておけば往復が閉じます。

ここまでの結果を HANDOFF.md に書いて、プッシュしておいて。

よくある勘違い

思いがちなこと実際は
クラウドの私は、PC のファイルも見られる見られません。まったく別のパソコンです
新しいチャットでも、前の話を覚えている覚えていません。ファイルに書いたものだけが伝わります
作ったものは自動で保存されるされません。GitHub に送り返して初めて残ります
PC で git pull すれば最新が来る本棚（main）の最新が来ます。作業台の中身は、そのブランチを指定しないと来ません
GitHub は公開の場だから危ない公開／非公開は選べます。ただし今の portable-out は公開設定です（下記）
このリポジトリは「公開」設定です

Okinaga-8/portable-out は誰でも見られる状態になっています。README の「ログインなしで開ける」はそういう意味です。

プログラムや手順書を置くぶんには問題ありませんが、ComfyUI のワークフロー（.json）にはプロンプトの文章とローカルの絶対パスがそのまま入ります。それを置くと世界中から読めてしまいます。置きたい場合は、先に非公開に切り替えてください（GitHub のリポジトリ → Settings → 一番下の Danger Zone → Change visibility）。
